Description of the Artifact
The Treasure Hunt intelligent agent project, which I first finished in CS 370: Current and Emerging Trends in Computer Science, is the artifact I chose for the algorithms and data structures category. The project trains an intelligent agent to navigate a maze and find a prize using Python, TensorFlow, Keras, and deep Q-learning. Through frequent interactions with the environment, the agent gains knowledge and is rewarded or punished according to its actions. The project incorporates reinforcement learning concepts such as Q-values, experience replay, epsilon-greedy exploration, and neural network training to determine an effective path through the maze.	

Rationale for Inclusion

I chose the Treasure Hunt project for my ePortfolio because it shows how I can use data structures and algorithms to solve challenging computer problems. The deep Q-learning technique necessitates that the agent assess potential courses of action, store past experiences, and utilize those experiences to make better decisions in the future. To make the training process better, I added valid-action selection, which allows the agent to only consider legitimate maze motions. Additionally, I updated the epsilon-greedy exploration approach, provided reproducibility parameters to enable more consistent evaluation of training outcomes, capped the number of steps permitted during an episode, and developed a target network to enhance training stability. I also added performance indicators for loss, win rate, epsilon, and number of steps, and improved the experience replay implementation with a bounded deque. These modifications show a deeper comprehension of data structures, algorithmic decision-making, and reinforcement learning while making the system more structured, quantifiable, and effective.	

Course Outcomes

The improvement made it easier for me to illustrate the course objective of utilizing algorithmic concepts to design and assess computing solutions while taking trade-offs into account. I assessed the intelligent agent's ability to choose actions, store experiences, investigate its surroundings, and learn from past results. I had to consider trade-offs between exploration and exploitation, training duration, the maximum number of steps permitted per episode, and the quantity of experience data kept for training because of the improvements. The deliberate choice of a data structure that restricts memory development while maintaining current events for learning is also demonstrated using a bounded deque for experience replay. By preventing the agent from purposefully choosing motions that were not feasible within the maze, valid-action selection greatly enhanced the decision-making process. This improvement also helps the results of delivering computing solutions by using creative and well-founded methods, abilities, and tools. I modified and tested a deep Q-learning solution using Python, TensorFlow, Keras, NumPy, and Jupyter in Visual Studio Code. To make it easy to assess the algorithm's behavior, I included training metrics and reproducibility controls. Instead of just developing an algorithm that generates an output, these improvements offer more convincing proof of my capacity to evaluate an existing computer solution and better its design. 

Reflection on the Enhancement Process

I now have a better knowledge of how individual design choices might impact an intelligent system's performance and maintainability thanks to the upgrade process. Transferring the old Treasure Hunt project into my current development environment was one of the most difficult tasks. I had to make the notebook self-contained and make sure that the labyrinth environment and experience replay capabilities functioned properly with the improved code because the old project relied on supporting classes and an earlier development environment. During the project's testing, I also ran into problems with duplicate training functions, which necessitated debugging the notebook and confirming which training algorithm version was being used. 

This technique taught me how important it is to test improvements gradually rather than doing a big training run right away. Before increasing the training effort, I evaluated the improved algorithm with a limited number of epochs and steps. The improved agent recorded loss, epsilon, steps, and training time during a 50-epoch test, successfully finishing six episodes and generating a rolling win rate of roughly 9.4%. The brief test showed that the increased training process was working and that the agent could make wise decisions, even if it was not meant to fully teach the agent. This process strengthened my debugging, algorithm analysis, and problem-solving skills and showed me the importance of measuring performance when evaluating changes to an intelligent computing solution.
